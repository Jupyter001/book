# 协作素材与提交流程

本仓库及 GitHub Pages 网站均为公开内容。所有进入 PR 的内容都可能被任何人查看、复制和索引。

## 资料放置位置

- `content/characters/<character-id>.json`：人物圣经，按 `content/characters/README.md` 说明填写，复制 `content/characters/template.json`。
- `content/milestones/<date>-<event-id>.md`：事件与里程碑，使用 `content/milestones/_template.md`。
- `content/photos.json` 与 `src/photos/`：已获公开使用许可的照片及描述。
- `content/stories/<work-id>.md` 与 `content/stories.json`：原文、剧本和分集索引。

## 先定主角团，再写分集

每位重要角色先复制 `content/characters/template.json` 建立人物圣经，按照 `content/characters/README.md` 补齐剧情定位、人物核心、性格细节、关系、行为边界、语言表演和成长弧线。关键人物设定和后续剧集一致性规则经作者/项目负责人审核并标记“已批准”之前，先不要把分集剧本当成定稿。

### 人物形象由合作者设计并入库

人物视觉设计由合作者使用其选择的文生图工具，或以获准的素材库图片为参考进行图生图/实图改造；仓库不代替设计工具自动生成形象。建议流程：

1. 在人物圣经中先写视觉锚点、标志性造型、不可变化项和可变化项。未知信息留空或标“待讨论”，不要靠模型猜测。
2. 从 `content/photos.json` 图片库挑选风格/服装/构图参考；记录被引用图片的 ID 及用途。若角色已有参考图，用获准的素材做图生图以保持身份与造型连续；若无合适参考，可文生图形成候选概念图。
3. 由合作者挑选/修订概念图、与主角团整体风格比对，并由项目负责人审核。只有获批后才指定为该角色的主视觉锚点。
4. 将获准公开使用的图片放入 `src/photos/characters/<character-id>/` 并登记到 `content/photos.json`；标题标明角色和用途（如“主视觉”或“服装参考”），描述注明角色 ID、设计版本、创作工具/模型（如已知）和使用许可。角色 Markdown 中反向记录图库资源 ID。
5. 后续改版不要覆盖旧图或无痕改设定。增加新资源 ID、升级人物设定版本，记录变化原因并经审核；剧本、分镜和参考图统一引用当前已批准版本。

AI 概念图也须确认工具条款允许项目使用和公开。不得上传未经许可的真人照片，不得要求生成可识别真人的仿制形象。多人参考图要标清每张图的用途，避免将服装/风格参考误认成角色身份依据。

### 声音是可选项

人物圣经可选填声音设定（音色、语速、口音、情绪范围、参考台词），留空表示不锁定声音，不影响人物/剧本批准。若使用配音或声音生成，再单独确认工具许可、演员授权；克隆可识别真人声音必须获得明确授权，不能因为照片或聊天内容已获准使用就推定声音授权。

## 隐私与来源

- 不要提交未经明确同意公开的群聊截图、完整聊天导出、真实姓名/账号、联系方式、私密对话或其他个人信息。
- 需要引用聊天或截图时，先取得相关参与者同意，再只写创作必要的脱敏摘要或短摘录；原始私密材料保留在获授权的私有位置，不放进仓库。
- 经所有可识别参与者同意、完成脱敏且确有创作需要的单张截图，可以作为图片素材放入 `src/photos/` 并登记到 `content/photos.json`；不得提交完整聊天导出或包含无关个人信息的原图。
- 涉及可识别真人的照片，确认所有相关人员同意公开使用；隐去无关人员、账号和通知等信息。
- 对人物设定和事件记录注明来源 ID、日期、同意状态和脱敏情况。未经证实的回忆、推测和创作建议要明确标注，不能当作事实。
- 如果授权状态不确定，先不要提交；在 PR 中说明缺少的授权或待核实事项。

## GitHub PR 流程

1. 从最新 `main` 创建分支，只提交获准公开的资料及其必要来源说明。
2. 为人物复制 `content/characters/template.json`，为事件复制 `content/milestones/_template.md`，填写来源、授权、脱敏和待确认信息。
3. 照片素材同时更新文件、`content/photos.json` 和描述/标签。
4. 提交 PR；由作者审阅事实、授权和剧本影响后再合并。自动检查通过不代表内容授权或事实已获确认。

## 使用 MiniMax Code Desktop

在 MiniMax Code Desktop 中打开本仓库，选择 **M3.1-Flash**，并将 `mcode-script-prompt.md` 作为本次写稿指令。检查模型生成的每处事实、人物设定和剧情改编，再把人工确认后的改动提交 PR。不要将未授权的原始群聊或截图粘贴到模型提示中。
