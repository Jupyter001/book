# Week 0：主角团人物圣经与形象设计

Week 0 是正式写分集剧本、分镜和视频之前的主创准备阶段。目标是让主角团“是谁、为什么这样做、看起来是什么样”先被共同理解并审核定版；后续内容以已批准的人物圣经和素材库主视觉为连续性基准。

## Week 0 完成标准

每位重要角色都需要：

1. 一份 `content/characters/<character-id>.json` 人物圣经，按 `template.json` 填写；人物动机、性格优缺点、行为边界、关系、语言风格和成长弧线均有足够信息供后续创作。
2. 有来源支撑的设定标明来源 ID；尚未确定的设定留在 `openQuestions`，不能由模型自行补成事实。
3. 一张经审核的主视觉图登记在 `content/photos.json`，并在 JSON 的 `visualDesign.primaryImageAssetId` 中引用；角色身份锚点、服装/配色、可变化项与禁止漂移项明确。
4. 人物圣经和视觉设计的状态都为 `approved`，并记录审核人、日期及设定版本。

主角团整体也应核对彼此外形易辨识、关系动机能相互推动剧情、人物视觉风格一致。任一重要角色仍未定稿时，可以继续讨论人物或制作图像候选，但不要把依赖该角色设定的分集剧本标为完成。

## 人物刻画要求

以“能指导编剧表演”为标准，写具体可观察的行为，不只堆形容词：

- **身份和剧情定位**：角色 ID、作品、主角团位置、核心功能、与主线的关系。
- **目标与驱动**：外在目标、内在需求、核心价值观、恐惧/顾虑；区分来源事实和虚构设定。
- **性格细节**：优势、缺陷、内在矛盾、压力下的反应、惯常决策方式，以及能体现性格的可观察行为。
- **人物变化**：成长弧线起点、关键转折、可能终点；转变需有事件和行为铺垫，不能为某集反转而突然改变。
- **关系与边界**：关系对象、信任/冲突来源、变化触发条件、人物的重要底线和不会轻易做出的行为。
- **语言与表演**：用词、句长、节奏、口头习惯、情绪表达和动作习惯；可用原创示例台词帮助维持语感。
- **事实边界**：真人经历、聊天信息和回忆只能在明确授权并经脱敏后使用；来源冲突或内容未核实，标记待确认。角色如为完全虚构，也在来源中说明。

## 角色形象图设计要求

图像由合作者使用合适的文生图工具，或基于已获准的素材库图像进行图生图/实图 AI 改造；本仓库提供设计规范和归档位置，不会替合作者自动出图。

### 设计输入

先填写人物圣经的 `visualDesign.identityAnchors`、`invariants`、`variableElements`，再开始出图：

- **身份锚点**：角色年龄感（不确定则不写精确年龄）、脸型/五官印象、发型发色、体态、肤色及可区分特征。避免只写“漂亮、帅气”等不可复现描述。
- **造型**：标志性服装、配色、配饰、材质，以及哪些会随场景变化。与角色职业、背景和剧情阶段相符。
- **画面**：本轮图像用途（主视觉肖像、全身造型或表情参考）、姿势、表情、视角、景别、构图、背景。
- **风格**：整部剧统一的媒介质感、光线、色彩和细节程度；主角团需容易区分，也要看起来属于同一个项目。
- **连续性**：同一角色的不同候选都重复引用相同身份锚点；不得把风格/服饰参考误当作人物身份参考。每张参考图都记录图库 ID 与用途。
- **输出**：主视觉尽量采用清楚的单人构图和无遮挡面部；要检查面部、发型、服装细节、手部和画面文字。概念候选未经审核前标记为 `candidate`，不可作为后续剧集的定稿参考。

推荐出图步骤：

1. 从图片库选取有明确授权的参考图，在角色 JSON 中登记 `referenceAssetIds` 和各图用途。只有风格/服装参考时要明确写出“只参考风格/服装，不参考人物身份”。
2. 文生图：用完整身份锚点和目标场景生成候选；图生图：明确哪些特征必须保留、哪些可以改动，不要把来源图中无关人物带入结果。
3. 对照主角团其他角色检查辨识度和统一风格；由合作者提出候选，项目负责人确认主视觉与不可漂移特征。
4. 将获批图片保存到 `src/photos/characters/<character-id>/`，登记到 `content/photos.json`。标题标明角色和图像用途；描述记录角色 ID、人物版本、参考图资源 ID、生成方式/工具（如已知）和授权状态。
5. 更新角色 JSON 的 `primaryImageAssetId`、`visualDesign.status`、审核记录和版本；不要静默替换旧图。更换主视觉时，新增图库资源 ID，记录原因与审核人。

### 可复制的提示词结构

按 `template.json` 的 `visualDesign.generationPlan.prompt` 字段填写。正向提示建议覆盖：

```text
项目统一视觉风格 + 角色 ID/虚构身份 + 身份锚点 + 标志性服装配色
+ 本张图的用途与姿势表情 + 景别视角与构图 + 背景 + 光线与色调
+ 细节质量要求 + 连续性要求
```

反向提示应列出本项目不希望出现的偏差，例如：`不同发色或脸型、错误年龄感、服装/配饰漂移、多余人物、遮挡面部、文字水印、低清晰度、错误手指`。按具体工具支持情况调整；提示词不是授权或审核的替代品。

### 授权与隐私

使用工具前确认其条款允许生成结果用于本项目并公开发布。不得上传未经许可的真人照片、完整聊天截图或个人信息，也不得要求仿制可识别真人。多人素材须取得所有可识别人员的许可并完成脱敏。未经授权状态确认的图片不得进入公开仓库。

## 统一 JSON 文件

将 `template.json` 复制为 `<character-id>.json`。保持 JSON 有效；数组没有内容时用 `[]`，未知的单值用 `null` 或写入 `openQuestions`，不要使用注释或编造占位设定。仅在内容可公开并获许可后，才提交文件和图库资源。

字段约定：

- `characterId` 与文件名一致；`displayName` 为项目内角色名；`version` 从 1 开始递增。
- `status`、`visualDesign.status` 使用 `draft`、`review`、`approved`。
- `canonFacts[].kind` 区分 `confirmed`（已确认事实）和 `fictional`（创作设定），并列出来源 ID。
- `visualDesign.primaryImageAssetId` 必须对应已批准、已登记的 `content/photos.json` 图片；候选图不作为主视觉引用。
- `canonFacts` 项包含 `statement`、`kind`（`confirmed` 或 `fictional`）和 `sourceIds`；`relationships` 项包含 `characterId`、`dynamic`、`trustAndConflict` 和 `changeTriggers`；`sources` 项包含 `sourceId`、`type`、`date`、`summary` 和 `permissionStatus`。
- `visualDesign.referenceAssetIds` 使用对象记录 `assetId`、`purpose` 和 `identityUse`（例如仅参考风格/服装，或经许可用于角色身份连续性）；`candidates` 项记录 `assetId`、`generationMode`、`prompt`、`referenceAssetIds` 和审核状态。
- `status` 与 `visualDesign.status` 开始都为 `draft`；只有项目负责人实际审核后才改为 `approved`，并填写审核人及日期。不得把占位模板直接当作已批准人物设定。
- 每次改动锁定设定或主视觉时更新 `revisionHistory`，由负责审核的人记录意见和日期。
- `sound.enabled` 默认 `false`。启用声音不等于获得真人配音或声音克隆授权；相关授权必须单独记录。
